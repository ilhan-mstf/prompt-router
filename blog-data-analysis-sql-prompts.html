AI Prompts for Complex SQL Queries, Pandas Transforms & Data Storytelling

Modern data analysts, analytics engineers, and data scientists spend a disproportionate amount of time wrangling messy CSVs, debugging intricate SQL window functions, and translating raw statistical outputs into executive-ready presentation slides.

While generative AI is proficient at writing code, poorly specified data prompts frequently lead to queries that produce Cartesian products, subtle off-by-one aggregation errors, or hallucinated database column names. Here is how to construct reliable data prompts that produce performant, production-ready analytics code.

The 3 Rules of Fail-Safe SQL Prompting

  1. Provide the DDL: Always include the `CREATE TABLE` schema definition with column data types.
  2. Provide Sample Rows: Give 2-3 sample records so the model understands data granularity and format (e.g., ISO timestamp vs UNIX epoch).
  3. Specify Dialect & Version: Explicitly state PostgreSQL 16, Snowflake, BigQuery, or MySQL 8.

1. Complex Window Function & Monthly Cohort Retention

Cohort retention queries are notoriously tricky to write by hand. Use this prompt to generate clean, optimized retention grids:

You are a Staff Analytics Engineer writing a performant PostgreSQL 16 cohort retention query.

Schema Provided:
```sql
CREATE TABLE user_events (
user_id UUID NOT NULL,
event_timestamp TIMESTAMPTZ NOT NULL,
event_type VARCHAR(50) NOT NULL
);
```

Task:
1. Define each user's signup cohort as the calendar month of their first event.
2. Calculate retention for Month 0 through Month 12 as both absolute active user count and retention percentage.
3. Use readable Common Table Expressions (CTEs) and window functions instead of nested subqueries.
4. Include comments explaining the partition boundary logic.

2. Pandas Data Wrangling & Missing Value Imputation

For data science and exploratory data analysis (EDA), prompt LLMs to write reproducible, vectorized Pandas pipelines:

You are a Senior Data Scientist writing a robust, vectorized Python Pandas data cleaning pipeline.

Dataframe Context:
- Dataset: 250,000 rows of customer transaction records.
- Issues: Missing values in 'income', string dates formatted inconsistently, categorical column with high cardinality and typos.

Instructions:
1. Write vectorized Pandas operations (avoid slow `.apply()` loops).
2. Impute missing numerical values using group-median based on 'job_tier' and 'region'.
3. Normalize text columns using fast regex string methods.
4. Add unit assertions (assert len(df) == original_len, assert df['income'].isna().sum() == 0).

3. Translating Metrics into Executive Data Stories

Executives do not want raw SQL tables; they want strategic insights. Use this prompt to convert query results into decision-making summaries:

Act as a VP of Business Operations communicating Q3 customer churn metrics to the CEO and Board.

Data Table:
[Paste raw table of churn by product tier, customer tenure, and support ticket count]

Write a 3-paragraph executive memo:
- Paragraph 1: Headline finding (the single metric that matters most and direction of trend).
- Paragraph 2: Root cause analysis based on correlation in the data.
- Paragraph 3: Two high-confidence, actionable interventions with expected revenue impact.

Frequently Asked Questions

Why do AI models generate SQL queries with non-existent column names?

If you ask an AI to write a query without providing the exact CREATE TABLE DDL schema, it will invent plausible-sounding column names. Always supply the exact schema and a 3-row sample table.

Which dialect of SQL do LLMs understand best?

Standard ANSI SQL, PostgreSQL, and Snowflake dialects are the most thoroughly represented in LLM training corpora. For specialized dialects like BigQuery or ClickHouse, explicitly specify dialect quirks in the prompt.

Can AI help optimize slow-running SQL queries with huge tables?

Yes. By pasting the EXPLAIN ANALYZE execution plan alongside the table indexing strategy, models like Claude 3.7 and GPT-4o can suggest composite indexes, partition pruning, and CTE materialization optimizations.
